# Web Style Atlas consumer

Resolve the atlas repository and observed revision. Read
[START_HERE](../../START_HERE.md), then the ready [catalogue](../../catalog/index.json).
Use the [selection procedure](../selection-guide.md) for candidate filtering,
choice modes, genuine preview paths and limited context loading. Use
[agent entry](../agent-entry.md) when maintenance and consumption are ambiguous.

Honor a known ready ID immediately. Honor “choose for me” without another choice
approval. Otherwise offer up to three compatible, structurally diverse ready
entries, each with a real preview, fit and tradeoff. Ask only one material
clarification. Report absent IDs honestly; never invent a catalogue entry or a
visual inspection. Preserve supplied brand constraints.

After selection, load only the chosen style's description, tokens, layouts,
asset rights and necessary reference. Record its exact revision, ID, variant,
3–5 invariants, adaptations and mobile behavior in design-decision.md in the
target project. Implement and check the actual website in its requested stack.
Do not modify the atlas or claim a queue task for a consumer request.

For a maintenance request, return to START_HERE's queue protocol and COST_POLICY.
Do not buy capacity, create extra agents or run unnecessary CI. Keep optional
platform adapters separate; a repo link alone does not install this skill.
