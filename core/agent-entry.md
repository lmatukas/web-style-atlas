# Consumer agent entry

Determine intent before loading context:

| User intent | Route | Write destination |
|---|---|---|
| Continue/add/fix this atlas | START_HERE maintenance → WORKFLOW and COST_POLICY | This repository, after a remote claim |
| Build a website using atlas directions | selection-guide.md → ready index → selected style only | User's target project |

Do not turn a consumer website request into an atlas task. A consumer does not
need to understand the work queue. A maintainer must not bypass the claim/PR
protocol. Explicit user batch/merge authorization changes only the requested
stopping point; required checks and protections still apply.

When consuming: honor a specific ready ID directly, honor “choose for me” without
a new approval round, otherwise present up to three genuine diverse choices.
Ask one material clarification at most. Never invent an unavailable ID or claim
to have opened an image when only metadata was available. Follow the full
procedure in selection-guide.md, then build and verify in the requested platform.

Use the repo skill by explicitly reading core/skill/SKILL.md, or install it only
through the host's supported skill mechanism when requested. Linking a repository
does not install a plugin or execute its instructions automatically.
