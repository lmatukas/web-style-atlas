# P76 — Ember Course Room: own hero for layout B

## Goal

Layouts A and B of Ember Course Room open with the same photograph
(`table.webp`). Give B its own hero from the asset bank so the two
compositions start differently.

## Read first

`START_HERE.md`, `docs/WORKFLOW.md`, `core/luxury-guide.md`,
`styles/ember-course-room/style.md`, `styles/ember-course-room/assets/RIGHTS.txt`.

## Depends on

P75 (canonical docs/progress.json).

## Allowed changes

`styles/ember-course-room/**` (reference pages, CSS, assets, `assets.json`,
`RIGHTS.txt`, `style.md`, QA, regenerated previews), `catalog/previews-manifest.json`,
`THIRD_PARTY_NOTICES.md` if it lists these images, `docs/evidence/P76.md`.

## Steps

1. Use asset bank image C-05 (candlelit dining room; 16:9 and 4:5 versions,
   ChatGPT image generation, 2026-10-25) as B's hero, with the 4:5 version on
   narrow screens.
2. Convert to WebP (about q80), strip metadata, keep the style's photographs
   under 1.5 MB and previews within the luxury-guide limits.
3. Record both files in `assets.json` and `RIGHTS.txt` with the full prompt
   from the bank manifest.
4. Keep A unchanged; keep text contrast with the existing overlay.

## Checks

`npm run validate`, `npm run build`, `npm run check`, unit tests, the style's
QA, browser and runtime QA, distinctiveness; before/after preview review.

## Done when

A and B open with different photographs, rights are recorded, PR merged with
green CI.

## Out of scope

Course images, other styles.

## Tracking and handoff

Follow `docs/WORKFLOW.md`. Evidence in `docs/evidence/P76.md`.
