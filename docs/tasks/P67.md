# P67 — Gallery: explain an empty filter result

## Goal

Filters combine with AND. A mix such as Families "illustrative" plus Use cases
"data" gives 0 directions, and the page only says "No directions match". The
visitor cannot see which filter caused it. Make the empty result explain
itself and show, for every filter option, how many directions it would give.

## Read first

`START_HERE.md`, `docs/WORKFLOW.md`, `gallery/README.md`, `gallery/gallery.js`,
`gallery/template.html`, `tests/browser/gallery.test.mjs`.

## Depends on

P66 (canonical docs/progress.json).

## Allowed changes

`gallery/gallery.js`, `gallery/template.html`, `gallery/gallery.css`,
`gallery/README.md`, `tests/browser/gallery.test.mjs`, `tests/gallery.test.mjs`,
`docs/evidence/P67.md`.

## Steps

1. Every filter option shows the number of directions it would give with the
   other current filters and search kept, e.g. "illustrative (4)". The "All …"
   option shows the count with that filter removed. Option values stay the same.
2. When the result is 0, list each active filter and the search term as a
   button such as "Remove Use cases: data → 3 directions", most useful first.
   One click removes that filter only. If no single removal helps, say so and
   point to Reset filters.
3. Keep keyboard use, focus, the live result count, URL state and reduced
   motion working. No new dependencies.

## Checks

`npm run validate`, `npm run build`, `npm run check`, unit tests and the
gallery browser test with a new case for the empty-state buttons.

## Done when

The empty state names the blocking filters and removes one on click; option
counts are correct; PR merged with green CI.

## Out of scope

Style metadata, filter categories, previews.
