# P08 — CI ir kokybės vartai

## Goal

Add truthful quality gates within the mandatory resource limits.

## Read first

`START_HERE.md`, `docs/WORKFLOW.md`, `docs/progress.json`.

Required plan sections: 9, 13.

## Depends on

P07 (canonical docs/progress.json).

**Priklauso:** P07.

## Allowed changes

`.github/workflows/`, kokybės skriptus, tikslinius testus ir npm scripts.

## Steps

šaltinių validacija, generated failų drift, preview freshness, browser smoke, prieinamumo patikra. PR tikrinti pakeistus stilius ir tuos, kuriuos paveikė bendri failai; leidimui – visus. CI nekuria commitų ir neperrašo bazinių vaizdų, kad paslėptų klaidą.

## Done when

tyčinis sugadinimas lokaliame fixture sustabdo atitinkamą patikrą; darbiniai šaltiniai praeina; dokumentuota kaip atnaujinti preview canonical aplinkoje. „CI paruoštas“ ir „GitHub CI praėjo“ žymimi atskirai.

## Mandatory cost constraints

Read `docs/COST_POLICY.md` before implementation. Acceptance also requires one
standard-Linux PR validation path; no duplicate push/PR suite; no scheduled runs;
concurrency cancellation; bounded timeouts; changed-style/dependency selection;
no browser/deploy jobs for tracking-only changes; failure artifacts retained for
one day; no LFS, paid runners or automatic AI reviews. Preserve required statuses
with a cheap dispatcher if necessary. Verify the effective workflow triggers and
retention settings without running a needless full CI cycle.

## Checks

Use a deliberately broken local fixture to prove each gate fails correctly. Inspect effective triggers, changed-scope selection, concurrency, timeouts and one-day failure artifact retention. Distinguish local readiness from an actual GitHub run.

## Out of scope

Do not create paid infrastructure, duplicate suites or scheduled runs; do not rewrite baseline previews or commits to hide failures. Follow docs/COST_POLICY.md.

## Tracking and handoff

Follow docs/WORKFLOW.md and docs/COST_POLICY.md. Update only this task’s record and regenerate docs/STATUS.md for tracking commits. Publish one implementation PR and evidence, set review on fresh remote main, then stop. Done requires a merged implementation and verified checks; never mark completion speculatively.
