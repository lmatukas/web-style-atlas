# P33 — S60 B route map height (P27-A05, #142)

Author: agent/01dpob2fr2xg

Checked: 2026-10-24

## Cause and change

The B `.chart-scene` wrapper was tall, but the `svg.route-map` inside it kept
a fixed viewBox: `800×1100` below 650 px and the landscape `800×680` above.
The real map was 495–536 px on phones and 359 px at 768, so empty wrapper and
caption filled the rest.

`reference/app.js`:

- below 1024 px the portrait chart is used, and its viewBox height is derived
  from the map's actual width so the map takes 76% of the window height
  (clamped to 1100–1500 units). Islands, route and stops are scaled to fill
  it and labels move with their stops;
- labels are clamped by their measured text width so no stop name leaves the
  map on either route;
- it refits on resize and removes that listener on `pagehide`.

`reference/style.css` gives map labels a readable size between 651 and
1023 px (it was about 10 px at 768). Desktop is unchanged.

`tools/qa.mjs` pinned the old literal viewBox `0 0 800 1100`. That line now
checks the meaningful property instead: a portrait viewBox (800 wide, at
least 1100 high) and the B map at least 70% of the first screen. The existing
label-bounds assertion stays as it was.

## Measurement

Actual `svg.route-map` intersection with the first viewport (not the wrapper):

| Viewport | Before | After |
| --- | --- | --- |
| 360×844 | 495 px, 58.6% | 641 px, 76.0% |
| 390×844 | 536 px, 63.5% | 642 px, 76.0% |
| 768×1000 | 359 px, 35.9% | 760 px, 76.0% |
| 1440×1000 | 734 px, 73.4% | 734 px, 73.4% |

Normal, reduced and blocked-WebGL modes gave the same values. A's sea scene
stays at 87.7–88.7%.

Labels for both routes (“bays”, “islands”) were checked inside the map at
360, 390, 651, 768, 1023 and 1440 px: all inside. Before the clamp, “Vakaro
uostas” was cut off at 768 and 1023 with the larger labels.
