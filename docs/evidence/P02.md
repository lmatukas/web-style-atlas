## Command and authoring behavior

- `npm run validate` validates all authored styles and shared registry/board.
- `npm run validate -- --style <id>` validates that style plus shared metadata;
  other styles' authored content is not loaded. Unknown IDs fail.
- `npm run build` validates all sources first, then emits per-style tokens.css
  and ready-only catalog/index.json and catalog/index.md. It needs no previews.
- `npm run build -- --style <id>` limits token writes while keeping the full
  validated catalogue indexes consistent.
- `npm run check` is read-only: it detects missing or stale generated text. It
  intentionally fails publication of any ready style until P03 supplies the
  preview freshness gate. It does not fabricate a browser/hash PASS.

Every style, including drafts, needs the four authored files and required
Markdown sections. Drafts may omit reference pages and have unfinished prose;
their declared assets must still exist and have explicit redistribution data.
Ready styles require both reference pages, style.css and a 700–1200-word body.
Only ready metadata enters public indexes. Both statuses get generated tokens.
Errors identify the originating file and JSON pointer or Markdown section.

Generated variables use --color-*, --font-display/body, --font-size-*,
--font-weight-*, --line-height-*, --letter-spacing-*, --spacing-*, --radius-*,
--shadow-*, --motion-duration-* (ms), --motion-easing-*,
--layout-content-max-width, --layout-text-max-width and --breakpoint-* (px).
Underscores in color role names become hyphens. Local font URLs resolve relative
to reference/tokens.css and retain their asset/license links. Breakpoint custom
properties document values; media queries must use numeric conditions. Reference
CSS implements reduced-motion behavior using the authored motion guidance.
