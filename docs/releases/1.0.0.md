## Acceptance and known limits

[Full catalogue audit](../evidence/catalog-review.md): all 96 actual A/B
computer/phone views reviewed, every prescribed close pair compared, every style
scored 11–12/12 without a zero. Five dense technical/documentary examples retain
compact secondary-label limitations; their detailed text records or full-diagram
link remain available. No palette-only duplicate was accepted.

[Original consumer trials](../benchmarks/p10/RESULTS.md): six actual fresh
`gpt-6-luna` target executions, three fixed briefs, the same service brief in three
directions and one React adaptation. The runtime exposed a model alias, not an
exact snapshot. [P13 replay](../benchmarks/p13/replay.json) is a later six-viewport
browser replay of two retained outputs, not a new independent model trial.
Native Codex CLI, Claude Code and IBM Bob runtimes were not installed or executed;
see [compatibility matrix](../compatibility.md). Automated axe and bounded visual
review do not establish complete WCAG conformance or universal originality.

All local reference controls are truthful demonstrations: category/search,
dates, choices, cart arithmetic and service outlines work, but no real order,
booking, live analytics or external message is created. A consumer website needs
its own verified content, business integrations and release checks.

## Reproduce the prepared source

Use the committed lockfile, Node 24.19.0 and Ubuntu 24.04 x64 for canonical browser
checks. A regular Node 24 host can build and browse the committed previews without
Chromium. Exact final execution results are retained in [P14 evidence](../evidence/P14.md).

```sh
git clone https://github.com/lmatukas/web-style-atlas.git
cd web-style-atlas
npm ci --ignore-scripts --no-audit --no-fund
node scripts/ci-scope.mjs --full
node scripts/ci.mjs validate
npm run check
npx playwright install --with-deps --only-shell chromium
node scripts/ci.mjs browser
git diff --exit-code
npm run dev -- --base /web-style-atlas/
```

Version metadata is part of conservative render provenance. All 96 frames were
rendered canonically after the 1.0.0 package/lock change; their output hashes were
identical to the accepted images, so no duplicate PNG bytes were committed.
The manifest now binds every frame to the current release inputs.

## Publish the prepared main revision

Publication is authorized by the owner's final-queue instruction. The connected
GitHub app exposes no workflow-dispatch operation; it cannot start this run or
change Pages administration. Pages was already enabled and verified in P12, so
there is no need to change its settings again.

1. After the P14 implementation PR is merged, open
   [Actions → Verify release and optionally publish Pages](https://github.com/lmatukas/web-style-atlas/actions/workflows/release.yml).
2. Choose **Run workflow**, branch **main**, enable **publish**, then press
   **Run workflow**. This is one publication run; a failed gate prevents upload
   and deployment. Other branches do not run the release job.
   Start a new run: rerunning failed run
   [39582682091](https://github.com/lmatukas/web-style-atlas/actions/runs/39582682091)
   would check its old pre-P14 revision and fail the obsolete 12-style assertion.
3. Wait for both **verify** and **deploy** to succeed. Open the actual
   `github-pages` environment URL. Confirm **24** style cards, search/reset,
   three-way comparison, B/mobile, prompt copy and one real reference page.
   Record the workflow run, deployed source SHA and opened example in P14 evidence.

The owner completed this manual publication in run 39585598844, and the live
interaction checks above are recorded in P14 evidence. These steps remain the
procedure for a later authorized update; a source or documentation merge alone
does not update Pages. No tag or GitHub Release was created; neither is required
to use the Git-backed catalogue or the Pages deployment.

The workflow remains manual only, with full 24/48/96 validation, ordinary Linux
runners, bounded timeouts, no dependency cache, one-day static artifact retention
and tiny failure-only diagnostics. Tracking commits do not deploy the site.
