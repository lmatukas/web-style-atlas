Keep these features of the direction: a disciplined column grid; headings that span several columns while labels take one; numbered horizontal service divisions; generous unfilled space beside dense information.

Composition A: a numbered service index with a large opening proposition. Composition B: an asymmetric work catalogue with a narrow identity rail. The brief below describes both; build the chosen one. B has a different content structure and flow of use, not just a different order. In both versions keep the same palette, type voice and honesty rules.

## Original creative brief

Create your own visual expression: original copy, illustrations, composition and details. Use only your own or properly licensed assets. Do not carry over other brands, code, recognisable scenes or combinations of them. Mark the working demonstration name clearly as invented; use real facts only once the user provides reliable content.

The project is FORM / ORDER, an invented independent design practice that builds identities and information systems for cultural organisations. A visitor should quickly understand what the studio does, inspect sample work and find a real next step. Mark the studio, its history and its projects as fictional.

Palette: off-white paper #f2f1e9, a light grey surface #e6e5dc, near-black text #181818, grey labels #55554d, one red signal #be2e20, rules #66665d and a red focus outline #a72317. Use one plain sans serif (Arial or a licensed neo-grotesque) for everything, with large weight and size contrast instead of a second typeface. Keep a consistent left edge; do not centre headings. The red signal could become another accessible brand colour, but the grid relationships must stay.

Composition A, the service index: a compact identity with visible numbered navigation (01 Services, 02 Method, 03 Selected work) and a small location and tagline line. A very large proposition such as "Clarity, by design." shares its baseline grid with a short studio description and a quiet link down the page. A large red circle, drawn in CSS, balances the oversized text; it is geometry, not a product image. Then four full-width ruled service rows, each pairing a number, a short service name and one concrete deliverable. A three-stage process strip (listen, arrange, resolve) reads left to right. Close with a native details element answering "What does a first engagement look like?", a contact section that says plainly it is a demonstration, and a short colophon.

Composition B, the work catalogue: a narrow persistent identity rail with the studio name, a period label and a compact project index (01, 02, 03). The main area alternates wide and narrower project studies, each an original CSS typographic composition with a number, a title and a one-line caption (client type, discipline, year). They are typographic specimens, not thumbnails standing in for missing photos. Finish with a short note on the method, a link back to the practice and a colophon.

Use only text links and native disclosure; no drawer, modal, carousel or contact form without a backend. Focus outlines are offset and clear. On a phone all navigation stays visible and wraps, the large type steps down before anything else shrinks, service rows stack number, name and deliverable in reading order, and the B rail becomes a short header above the catalogue.

## Final check

Check 360, 390, 768 and 1440 px widths for both compositions. There is no required motion: only short colour transitions on links, removed by prefers-reduced-motion; every section is complete in a still screenshot. Check keyboard focus, contrast on every real text background, the console and that there is no horizontal scrolling. A static screenshot alone does not prove that a control works; operate each one.

Functional acceptance: Navigation and the project index reach real sections; the engagement disclosure works with a keyboard; the contact area gives honest guidance instead of a fake form or broken email link.

Mark the demonstration project clearly in the page footer.

Deliver a working preview, a summary of the checks actually run, the origin of assets and the remaining limits. Publish publicly only when the user asks. Finish the implementation; a plan alone is not a result.
