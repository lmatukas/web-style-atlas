# Obsidian Stage — website creation prompt

Build a working website in the user's project. This is a self-contained creation prompt; do not change the atlas or its task registry.

## Adapt to the project

- Brand and business: [FILL IN YOUR OWN OR KEEP THE DEMONSTRATION].
- Audience and main action: [FILL IN].
- Approved content, specifications, prices and integrations: [FILL IN OR KEEP A CLEARLY INVENTED DEMONSTRATION].
- Project technology and environment rules: [FILL IN OR APPLY THE EXISTING ONES].
- Composition: [A OR B; default A].

If the fields stay empty, use the invented demonstration name "Veylqor" and an original portable audio recorder. If they are filled in, rely only on approved information. Keep the five signature features: a dominant metal object, one sans typeface, one feature and one number per scene, a meaningful construction breakdown on scroll, and a light selection area with an exact total.

Composition A: a black single-device stage, five construction chapters and a light configurator. Composition B: a light comparison of three models, a specification matrix, the configurator and a dark close. B has its own structure and flow; do not reuse the A chapters with only a new background.

## Original creative brief

Write your own copy, proportions, device, composition and motion. Do not copy a real manufacturer's silhouette, website or scenes. Veylqor is an invented demonstration project. Do not claim awards, real customers or manufacturing facts. Sample numbers and prices are clearly marked as demonstration values everywhere.

Create an original handheld audio recorder: a slim rounded metal body, a large round ring of glass and light, microphone slots and one recessed record button. Draw the object with real native WebGL, without a CDN or an imported model. Use depth testing, real volumes, surface normals and directional light. Provide an SVG or PNG fallback with the same recognisable parts, plus an informative exploded view of the layers. No AI-generated images or photographs are needed.

Palette: black #000000, graphite #1d1d1f, light text #f5f5f7 and one cool #a5d8f6 accent. The selection area is light, with dark text. Type: one local OFL geometric sans family, 400 for text and 600 for headings; no serif. Campaign heading up to 80 px, 36–56 px on a phone. Small uppercase labels have 1–3 px letter spacing; paragraphs stay within 32–36 characters. Local WOFF2 files must include Lithuanian letters and the full OFL.txt; total font size up to 200 KB.

One large object owns the first screen, with a visible height of at least 70% of the viewport. Next to it: a small label and the short heading "Hold on to what remains." One main action: "Explore the device". Give the phone its own composition: a clear heading, a large object and reachable controls. Do not squeeze the desktop layout.

In layout A, after the intro, build five sticky scenes: form / 86 grams; construction / 3 layers; recording / 48 kHz; time / 18 hours; whole / 1 action. Each scene holds only one feature, one number and a short explanation. As the visitor scrolls, the device turns, its glass, electronics and body separate, then come back together. Do not hijack scrolling and do not trap keyboard focus. The last chapter is a light selection desk.

In layout B, start with three models on a light background. Show images of models 01, 02 and 03 and a comparison table. 01: 86 g, 48 kHz, 18 h, €249. 02: 104 g, 96 kHz, 24 h, €349. 03: 122 g, 192 kHz, 30 h, €449. Base storage is 32 GB for every model. These are invented demonstration values, not a real commercial offer. On a phone the table scrolls inside its own region; the page itself never scrolls sideways.

Build the same real local feature in both layouts. The model sets the base price. Graphite is included; the frost finish adds €20. 32 GB is included, 64 GB adds €40, 128 GB adds €90. Total = model + finish + storage surcharge. The finish changes the object's material; every choice updates the text and price summary. Before the summary is created, the visitor must confirm that this is a demonstration; a missing confirmation shows a clear error and moves focus. The summary names the exact model, finish, storage and total. Reset returns to 01 / graphite / 32 GB / €249 and clears the confirmation. Make no real payment, order or data transfer.

Motion: an initial turn of up to 1400 ms, then it stops. After that only the visitor's scroll, arrow keys or a horizontal swipe move it. Pause stops the animation and the automatic response to scrolling. Reduced-motion mode shows the local, informative static object right away, with no animation loop. Unavailable WebGL and a lost context show the same clearly labelled fallback. All HTML content and the feature always work. Stop work when the window or the scene is hidden; on pagehide, free GPU resources and observers. No audio API is needed.

## Final check

Check both layouts at 360, 390, 768 and 1440 px. Test rotation, choices, the error, the summary and reset with a mouse, touch and keyboard. Recalculate all 18 combinations of model, finish and storage. Check the real 3D draw calls, the layers that open and close on scroll, pause, context loss and resource cleanup. Check reduced motion and blocked WebGL separately. A static image alone does not prove working 3D.

Review the four final A/B desktop/phone images, visible focus, contrast, the console and font loading. Make sure there are no external requests, empty links, fake purchases or hidden choices. Mark the demonstration project clearly in the footer. Deliver a working preview, a summary of the checks you actually ran, asset provenance and the remaining limits. Publish only when the user asks for it. Finish the build; a plan alone is not a result.
